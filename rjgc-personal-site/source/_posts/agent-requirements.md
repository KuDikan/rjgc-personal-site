我发现，和 Agent 协作的关键不是把句子写得很长，而是给出**清晰的目标、约束和验收标准**。

## 模糊需求的问题

"帮我做个个人网站"——这句话里没有：

- 用户是谁
- 页面应该包含什么内容
- 有什么技术约束
- 怎样算完成

Agent 只能靠猜。猜得好是运气，猜得差就得反复返工。

## 可验收的需求长什么样

把它拆成五个部分：

1. **用户**：谁会打开这个页面
2. **内容**：页面上必须出现哪些信息
3. **约束**：技术栈、样式规范、禁止事项
4. **完成标准**：怎样算做完了
5. **禁止事项**：不要替我做什么

最后一条最容易被忽略，但其实最有用。比如"不要替我执行 `git push`"，
"不要修改我的全局 Git 配置"——这些约束保护的是你的操作边界。

## 验收标准要能被检查

"页面要好看"无法检查。"正文最大宽度 800px"、"所有个人信息均可见"可以检查。

能写成断言的验收标准，就应该写成断言。哪怕只是构建脚本里的一次检查，
也比"我记得好像加了"要可靠得多。

## 落到实践

这个网站就是这么来的：

```text
提出需求 → 明确验收标准 → 实现 → 本地验证 → Git 提交 → 自动部署
```

每一步都能验证，所以出问题时能精确定位到是哪一环。
