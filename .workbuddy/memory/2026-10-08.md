## 导航栏美化：中文文案 + 去掉无意义下箭头

用户要求："标签栏美化一下，status 之类的改成中文，不是二级菜单的不要有下箭头"。

### 下箭头的成因

主题 `layout/_partials/sidebar/menu.pug` 的规则：
- 菜单值为**单值**（`key: /path/ || icon`）→ `li.item`，**无箭头**
- 菜单值为**对象**（`key: {default: ...}`）→ `li.item.dropdown`，**带箭头**

对象里**只有 `default` 一个子项时也会出箭头**，点开却是同一个页面。
我原先把 about/papers/rss/wiki/status 都写成了对象，于是 5 项全带箭头。

改为单值；只有 `posts` 是真多入口（文章/归档/标签），保留箭头。
最终结构：首页 / 关于 / 文章▼(文章·归档·标签) / 论文 / 订阅 / 知识库 / 状态

### 中文文案的坑（第一次写错了，静默失效）

主题 menu.pug 用 `__('menu.' + name)` 取文案，自定义键
（papers/rss/wiki/status）不在 `languages/zh-CN.yml` 里就回退显示英文键名。

补齐方式：新增 `source/_data/languages.yml`，走主题内置的
`before_generate` 合并机制（`scripts/generaters/config.js`），不改主题源码。

**关键结构**：主题执行的是 `data.languages[lang]`，而 `data` 本身就是
本文件解析后的结果（因为文件名是 `languages.yml`），所以**语种键必须在顶层**：

```yaml
zh-CN:          # ✅ 正确
  menu:
    papers: 论文
```

写成 `languages: {zh-CN: {...}}` 会让 `data.languages` 变成 undefined，
整个覆盖失效且**无任何报错**。我第一次就踩了这个坑，靠本地验证才发现。

### 自写校验的两个缺陷（都靠回归测试发现）

1. 断言正则 `[\s\S]{0,300}?` 会**跨越 `</li>` 边界**，导致从更早的普通
   `<li class="item">` 开始匹配、拿到错误 class，使箭头断言完全失效。
   改为 `(?:(?!</li>)[\s\S]){0,400}?` 限定不跨块，并加逐个 `<li>` 扫描作回退。
2. 注入回归的脚本本身匹配失败（产物里 `<li class="item"><a` 之间**无空格**，
   我的注入正则是 `class="item">(\s*<a`，故未命中，测试假通过）。

教训：**校验脚本自身也要做注入回归测试**，否则"断言通过"可能只是断言没生效。

线上已验证：CI 两 job 绿灯，导航栏形态与本地一致。

## 关键：after_generate 改产物的三个坑（踩了三次）

封装在 `scripts/lib/route-transform.js`：

1. **`after_post_render` 太早** —— 在 post.js 内部逐篇触发，locals 只含
   已处理的那几篇，用它建索引会漏掉大部分文章。
2. **直接改 public/ 文件无效** —— after_generate 时**文件尚未落盘**
   （public/ 目录都可能不存在）。症状极具误导性：日志打印"已改写 5 个文件"，
   产物里一个改动都没有。
3. **不能就地改 RouteStream** —— 其 `_data` 在构造函数里赋值并捕获，
   之后再改不被读取；且 `route.get()` 返回的是 RouteStream 包装器，
   直接包装会得到"stream 套stream"。

正确做法：`route.set(path, { data: fn, modified: true })`。
包装的是函数本身，求值时机仍在 flush 之后，拿到的正是最终 HTML。

没配Algolia 时整段分支连同动态 import 被 tree-shake，
**产物里连常量字符串都搜不到**。所以"按钮渲染出来但没有监听器"。
官方文档给的正解是 Pagefind（本地、无凭据），但需额外 CLI 索引步骤。

重写为完全自包含：自建 #search 弹窗 DOM + 自建输入框 + 捕获阶段监听。
主题的弹窗/输入框都由被摇掉的分支创建，本场景不存在。

### 网易云歌单：元数据能取，音频取不到

- 元数据：`music.163.com/api/playlist/detail?id=<歌单ID>` 可用（200 首，
  含歌名/歌手/专辑/时长/封面）。注意返回结构是 **`{result:{...}}`** 而非新版的 `{playlist:{...}}`。
- 音频：CDN `m*.music.126.net` 全部 **403**（带不带 Referer 都一样），
  `/api/song/media` 也不再返回 url。→ 音频必须用户自备，放 `source/audio/`。

### 三个新踩的坑

1. **音频目录不能放 `source/_data/assets/` 下**——主题 images 生成器
   对该目录逐文件 readFile，嵌套子目录触发 EISDIR。改放 `source/audio/`。
2. **`String.replace('</body>', ...)` 只替换第一处**。两个注入插件共存时，

3. **字符类白名单不能枚举"安全字符"**。音频路径校验写成

   （`/audio/` 前缀 + 无 `..` + 扩展名），真实防护交给 `safeUrl()`。

## 改用主题内置搜索（Pagefind）与播放器（nyx-player + meting）

用户指出应优先用主题自带能力，查官方文档确认：
<https://docs.shokax.kaitaku.xyz/features/search/> 明确支持
**Pagefind（本地，推荐）** 与 Algolia（远程）。此前自写 local-search.js
属重复造轮子——**动手前应先查官方文档**。

### Pagefind 的关键坑

它是**构建后**索引，不在 `hexo generate` 内部：
```
hexo generate && pagefind --site public
```
漏掉→ 搜索可点但无结果且不报错（与 Algolia 缺失时症状一模一样）。
npm scripts 里的 `build:search` 与 GitHub Actions 的手写步骤**是两处**，
改一处忘另一处→ CI 失败。已两处同步。

产物里 wasm 文件名是**无扩展名的 `wasm.unknown.pagefind`**（68KB），
不是 `.pf_wasm`。

### meting 是网易云音频的正确解法

网易云官方音频 CDN 直连 403，但 **meting（APlayer 的元数据后端）
代理后可用**：
- 歌单：`?server=netease&type=playlist&id=<歌单ID>`
- 音频：`?server=netease&type=url&id=<歌曲ID>` → 302 到带签名的 CDN URL → 206 audio/mpeg

用户提供了 https://meting.mikus.ink/ 这个自建实例。换实例用 `METING_API`。

**教训**：遇到"接口能拿元数据、拿不到数据本体"时，先找成熟的代理方案，
不要立刻转成"让用户自己准备素材"。

### 主题内置播放器的用法

`{% media audio %} ... {% endmedia %}` 是 **ends 标签**，体内是 YAML 数组，
主题 JSON.stringify 后塞进 `<div class="player" src='...'>`。
需要 `modules.player: true`。渲染在**正文内**（inline），不是悬浮。

### esbuild lockfile 漂移（第二次）

wrangler 精确锁 `esbuild 0.28.1`，但npm 元数据里出现更新的 0.28.x 后
解析漂移 → 本地 `npm install` 正常、CI `npm ci` 报 Missing。
**根治方式：`overrides` 把 esbuild 及 25 个 @esbuild/* 平台包钉死**，
而不是重新生成 lockfile（上次就是这么做的，所以复发）。

## 播放器按钮点不了（第二次修播放器）

### 根因：主题播放器只读 front-matter，不读 {% media %}

查主题源码确认了完整链路：

```
layout/_partials/layout.pug   if page.audio → CONFIG.audio = JSON.stringify(page.audio)
js/_app/player.ts            initAudioPlayer() 遍历 CONFIG.audio，
                             取 item.title 与 item.list[0] 传给 nyx-player
js/_app/pjax/domInit.ts      if (__shokax_player__) await initAudioPlayer()
```

**正文里的 `{% media audio %}` 标签与此完全无关**——它只把数据塞进一个
无人读取的 `<div class="player">`。正确做法是把播放列表写进front-matter：

```yaml
audio:
  - title: "我不难过"
    list:
      - "https://meting.mikus.ink/api?server=netease&type=url&id=287398"
```

上一版只写了 media 标签 → 产物 `audio: undefined` → initPlayer 收到空列表
→ 按钮在、点了没反应。**页面存在 + 元素齐全 + JS 加载 = 全都正常，
唯独功能是哑的。**

### 工具栏按钮不是页面里的元素

播放器 UI（`#playBtn` / `#showBtn`）由 domInit 用 JS 动态注入到工具栏，
**产物 HTML 里根本查不到**。所以校验只能验数据侧（CONFIG.audio），
不能断言"按钮存在"。

### 自己踩的第二个坑

生成的说明文字里写了字面量 `{% media %}`，被 Hexo 当成真标签解析，
构建报 `Template render error: unexpected end of file`。**在生成内容里
写模板语法必须转义或改用纯文本描述。**

### 校验脚本的坑

解析 CONFIG.audio 时不能用 `[\s\S]*?\]` 找结尾——音频地址里含 `]`
（如 `?id=287398`），会截在字符串中间导致 JSON.parse 失败。
必须用**括号计数**找配对的 `]`（并在字符串内跳过转义）。

### 教训（第四次同源问题）

这一类故障的共同点：**"存在性"检查全部通过，功能是哑的**。
已建立的检查清单：
| 功能 | 必须断言的东西 |
|---|---|
| feed | 内容含真实条目，非未渲染模板 |
| 数据面板 | 构建期渲染，非占位 div |
| 搜索 | public/pagefind/ 索引存在 |
| 播放器 | CONFIG.audio 非 undefined 且有 list[0] |
| 菜单 | 图标名在字体中定义 |
| 音频可播 | content-type 是 audio/* |

## 播放/暂停图标不切换（用户提供关键线索）

### 用户的研究结论是对的

ShokaX 的播放按钮图标靠 `#tool` 上的 `playing` class 切换：

```styl
#tool {
  .play-pause::before { @extend .i-play:before; }      // 默认：播放三角
  &.playing .player {
    .play-pause::before { @extend .i-pause:before; }    // 播放中：暂停图标
  }
}
```

编译后规则确实存在：`#tool.playing .player .play-pause::before { content: "\f06a" }`
（在 post.css / page.css / scaffolding.css 里各有一份）。

### 但 ShokaX 0.5.4 自己不加这个 class

`js/_app/player.ts` 只做：
```ts
initPlayer('#player','#showBtn',urls,'#playBtn','html[data-theme="dark"]','shokax')
```
**没有任何代码给 #tool 加删 playing**。

nyx-player 内部确实有 playing 状态（Pinia store：
`actions: { start(){this.playing=true}, paused(){this.playing=false} }`），
但那状态只驱动它自己的 Vue 组件，**不会写回 #tool 的 class**。

→ 于是 `&.playing` 分支永远进不去：**播放正常、图标不动**。

### 修复

`scripts/player-playing-class.js`：监听 `<audio>` 的
play/playing/pause/ended/error/loadedmetadata → 增删 `#tool.playing`。

**为什么监听 audio 而不用播放器 store**：
- audio 是播放状态真实来源，不依赖库内部实现；
- nyx-player 是压缩产物，store 未对外暴露，跨版本不稳定；
- 主题将来若自己修好，本实现只是重复设同一个 class，不冲突。

pjax 换页会重建 #tool → `pjax:end` 重新绑定并先清遗留 class；
另加 1.2s 兜底重试（主题 domInit 是异步插入 #tool 的）。

### 排查陷阱：CSS 规则不在 app.css 里

`#tool` / `play-pause` 规则在 **post.css、page.css、scaffolding.css**，
**app.css 里一条都没有**。我起初在 app.css 里搜了半天以为是压缩掉了。
校验脚本要遍历 `public/css/*.css` 而不是只看 app.css。

### 校验

validate.mjs 新增两项，缺一不可：
1. 同步脚本已注入（含 add/remove playing 调用）；
2. CSS 里存在 `#tool.playing ... .play-pause` 规则——**加了 class 但规则缺失
   同样表现为"图标不变"**，只看第1 项会漏。

离线用最小 DOM 替身跑产物里真实的脚本，7 个状态转换全通过：
初始→play→pause→再play→再pause→ended→再play。

### 协作收获

用户自己读主题 CSS 找到了 `playing` 这个线索，直接指出了方向。
**用户对代码的观察比我的盲猜可靠**——这类问题应该先请用户描述现象背后的机制。

## 字体：#brand .artboard 覆盖失效 + 接入 ZeoSeven 字体

### 为什么之前的覆盖没生效（用户提供线索）

产物 page.css 里有**两条** `#brand .artboard`：
- line 863：我的（custom.styl）
- line 3005：主题的 `brand.styl`（font-size: 3em / 系统字体栈）

选择器相同 → 优先级相同 → **后者胜**。
而 custom.styl 是被**追加到主题样式之前**的，所以主题那条赢。

**修复**：改用 `#brand .logo .artboard`（多一层 class）稳定压过。
通用教训：ShokaX 的 custom.styl 不是追加在末尾，
**同优先级覆盖无效，必须提高选择器权重**。

### 字体接入（Yozai Medium / LXGW WenKai Medium）

用ZeoSeven 的 cn-font-split 分片服务：
```
https://fontsapi.zeoseven.com/192/medium/result.css  → Yozai Medium
https://fontsapi.zeoseven.com/292/medium/result.css  → LXGW WenKai Medium
```
每个 @font-face 带 `unicode-range`，单片约 5 KB，浏览器按需下载。
完整 TTF 是 15 MB / 25 MB，直接用不可接受。
（Fontsource 虽有 lxgw-wenkai，但只有 latin 分片，中文不适用。）

新增 `scripts/font-inject.js` 把 `<link>` 注入 `</head>` 前。
不用 @import（阻塞渲染）、不用 fetch 后注入（会闪默认字体）。

### 主题 font 配置的两个坑

**坑1：变量 bug**（`_variables.styl` 第 15 行）
```styl
$font-family-logo = get_font_family('logo'), ... if get_font_family('title')
                                                        ^^^^^ 条件用的是 title
```
只设 `logo.family` 不设 `title.family` → **不生效**。两处都要写。

**坑 2：family 只能是单个字体名，不能含逗号**
`get_font_family()` 把它当单名返回，Stylus 拼接时加引号。
我写成 `'LXGW WenKai Medium, -apple-system, PingFang SC, ...'` 后产物变成：
```css
font-family: 'LXGW WenKai Medium, -apple-system, PingFang SC, ...', -apple-system, ...
```
浏览器找不到叫这个名字的字体 → 直接回退系统默认。

正确写法：`font.global.family: LXGW WenKai Medium`（只写名字），
后备栈由主题自己的 `$font-family-chinese` / `sans-serif` 补上。

### 最终产物（线上实测）

```css
body                → 'LXGW WenKai Medium', -apple-system, "PingFang SC", ...
#brand .artboard    → 'Yozai Medium', 'LXGW WenKai Medium', -apple-system, ...
```
两处 font-family 规则并存但**字体名一致**，无论哪条胜效果都对——
这是比单纯提高优先级更稳的写法。

### 未验证项

字体**实际渲染效果**没在浏览器里确认（无头模式拿不到字体渲染结果）。
用户反馈"字体加载失败"的话，改自托管：下载分片到 `public/fonts/`。

## Waline 表情尺寸：弹窗 2.3em，正文 8em

### 被覆盖的原始规则（/css/waline-*.css）

```css
.wl-emoji-popup .wl-emoji { max-width:1.5em; max-height:1.5em }        /* 用 max-* */
.wl-content .vemoji, .wl-content .wl-emoji { height:1.25em }          /* 用 height */
.wl-emoji-popup button { width:2em; margin:.125em; padding:0 }         /* 按钮容器 */
```

注意两处尺寸属性**不同**：弹窗用 `max-width/max-height`，正文用 `height`。
覆盖时要跟着用对应的属性，写错不生效。

### 必须一并改的：弹窗按钮宽度

弹窗表情从 1.5em 放大到 2.3em 后，`button` 仍是 `width:2em; padding:0`，
表情会溢出按钮——hover 底色 2em 宽、表情 2.3em 宽，观感错位。
所以按钮也放宽到 2.6em。这是尺寸改动的直接后果，不是额外需求。

### 用 !important 而不是赌文档顺序

Waline 样式表是**异步加载**的：
```html
<link rel="stylesheet" href="/css/waline-*.css" media="none" onload="this.media='all'">
```
实测 page.css 在文档中位于 waline CSS 之后（同级特异性下能赢），
但顺序由主题注入位置决定，将来可能变。用 !important 不赌这个。

### 查证过的假警报：.wl-content.expand

Waline CSS 里有
```css
.wl-card .wl-content.expand { overflow:hidden; max-height:8em; cursor:pointer }
```
看起来会把 8em 的表情裁掉。但遍历**全部产物 JS** 后确认：
没有任何代码给 `.wl-content` 添加 `expand` 类
（siteInit.js 里的 expand 是导航下拉菜单的，不相关）→ 该规则休眠。
`.wl-card .wl-content` 基础规则也无 overflow/max-height，不裁切。

教训：**看到可疑的 CSS 规则要去找有没有代码真的应用它**，
否则会为不存在的冲突做无用功。

### vemoji 是 <img>

从 Waline 源码的选择器 `.md img:not(.emoji):not(.vemoji)` 可证。
所以正文表情只设 `height` 即按原始比例缩放，不会变形。

### 已知观感问题（留了开关，未擅自改）

保留了原始 `vertical-align: baseline`。8em 表情与 1em 正文同处一条基线时，
表情会从基线向上耸起、把行高撑得很高。custom.styl 里已写好注释掉的
`vertical-align: middle` 一行，用户反馈观感不好时取消注释即可。

### 防回归：custom.styl 哨兵

custom.styl 是**构建期**被主题读进来编译的（不是运行时 link），
一旦编译失败或被跳过，里面所有自定义样式会**静默消失**——
页面照常渲染、HTTP 200、无报错。

validate.mjs 新增 5b 段，用特征片段验证产物里确实有 custom.styl 内容：
`.wl-content .vemoji`、`.wl-emoji-popup .wl-emoji`、`#brand .logo .artboard`、
`mp-breathe`、`.data-panel`。

## Waline 访问量恒为 0（用户提供关键线索）

### 根因：两个路径来源不一致

ShokaX 有**两处**给 Waline 传路径，取值来源不同：

| 位置 | 取值来源 | 实际值 |
|---|---|---|
| `layout/_partials/post/footer.pug` 的 `data-path` | Hexo 构建期 `post.path` | `/about/index.html` |
| `js/_app/components/comments.ts` 的 `walinePageview()` | 运行时 `window.location.pathname` | `/about/` |

而 Waline 客户端 `pageviewCount`（dist 源码）的逻辑是：

```js
const isDifferent = (el) => {
  const p = getPath(el)              // 读 data-path
  return p != null && path !== p     // 有 data-path 且与传入 path 不同
}
// 一致的 → 既查又增（Gn 会 +1）
// 不一致的 → 只查不增（u(c)）
```

`data-path=/about/index.html` ≠ `path=/about/` → 落进"只查不增"组：
- 浏览量 +1 记到 `/about/`（没元素展示它）
- 展示时查 `/about/index.html`（从没记过）→ **永远 0**

### 修复

`scripts/waline-path-fix.js` 在 after_generate 把 data-path 规范化：

```
about/index.html      → /about/
posts/foo/index.html  → /posts/foo/
index.html            → /
404.html              → /404.html   （文件式，无 index.html 可剥）
```

换算规则抽到 `scripts/lib/browser-path.js`，**修复与校验共用同一套**——
否则会出现"修复用一种规则、校验用另一种"互相放水。
scripts/ 是 CJS（Hexo 用 require 加载，不能同步 import ESM），
validate.mjs 是 ESM，用 `createRequire` 引它。

### 决定性验证

修完直接打 API：
```
GET /api/article?path=%2Fabout%2F&type=time  →  [{"time":31}]
```
**31 次访问一直都在**，只是之前用错的 key 去查。
这类"数据在、查错键"的 bug，直接打后端 API 一比就露馅。

### 校验踩的坑：不能要求"一律以 / 结尾"

第一版断言写的是 `!/index\.html$/ && !endsWith('/')`，
结果 `404.html` 的 `data-path="/404.html"` 被误报——
它的浏览器路径本来就是 `/404.html`，本来就对。
改成拿每个页面的 data-path 与该页 **canonical 浏览器路径逐一比对**。

### 通用教训

**同一个 key 在多处生成时，必须确认它们用的是同一套规则。**
本例中"构建期路径"与"运行时路径"形态不同，任何一方单独看都对，
只有合起来看才发现对不上。这类问题在静态站点 + 第三方服务组合时高发。
